Final Revision Guide
Where you stand
This version supersedes the earlier Round 2 draft. The thesis has a solid artifact, a useful evaluation question, and a quantitative benchmark whose headline values in Table 7.1 match the committed result file. The independent audit also found several issues that go beyond prose and layout, so the final pass must begin with research validity and reproducibility rather than copy-editing.
Bottom line: No supervisor can honestly guarantee a 6.0 before examination. Completing only the original checklist would not make the thesis a certain top grade because the current semantic baseline, benchmark execution, judgment provenance, statistical outputs, and user-study reporting still contain material weaknesses. Completing every gate below would make the thesis a credible top-grade candidate. Work in order: if a gate changes the results, regenerate every downstream table, figure, significance test, and claim.
Gate 1: repair the evidence before editing prose
Replace the mock semantic baseline and rerun the benchmark. In code/ranking/ai_semantic_baseline.py, AISemanticBaseline() currently defaults to MockEmbeddingProvider, which averages pseudo-random word vectors derived from Python's process-dependent hash function. That is neither a defensible AI semantic baseline nor fully reproducible. The recommended fix is to use a real multilingual sentence-transformer for the experiment, pin the exact model and revision, record the library versions and random seeds, and cache or checksum the embeddings. If this cannot be completed reliably, remove the semantic baseline and every comparative claim about it rather than presenting the mock model as semantic retrieval. Then regenerate Table 7.1, per-query metrics, confidence intervals, pairwise tests, win/loss counts, and all related prose.
Make the benchmark genuinely frozen and describe it as a reranking experiment. The production experiment code still calls the live CKAN package_search endpoint and computes recency from datetime.now(). All evaluated systems therefore begin from portal-generated candidates, and a future run can change when the portal or the date changes. Run the benchmark from one committed metadata snapshot with a fixed reference date. State the candidate-pool depth and make clear that the systems rerank a common portal-generated set; this design cannot measure recall for datasets that the portal candidate generator never returns. If the intended claim is end-to-end corpus retrieval, index the same frozen 500-dataset corpus independently for every system and rerun the study.
Repair the relevance-judgment provenance, schema, and scale. The public files currently tell three different stories. The interim auto/manual files contain grades 0-3, while evaluation/ground_truth_final.json—the file used for Table 7.1—contains grades 0-2. In evaluation/data/pooled_candidates.csv, judge1_grade, judge2_grade, and adjudicated_grade are identical for all 150 rows, so those fields do not evidence two independent assessors. Rebuild or relabel the schema to reflect the real single-author assessment and consolidation process; document any 0-3 to 0-2 mapping; and replace the misleading adjudicated annotator label if it does not describe an actual adjudication. The evaluation should fail if the final ground truth is missing instead of silently copying an auto-labelled fallback into the final filename.
Required metric statement: identify ground_truth_final.json as the authoritative file; define every final grade; state that MAP, P@5 and MRR treat grades greater than zero as relevant if that remains the implemented rule; and state that nDCG uses exponential gains of 2^grade - 1. The published judgments plus this paragraph must reproduce Table 7.1.
Make the user-study evidence auditable. Appendix A lists 10 questionnaire items, but Table 7.2 reports 21. Insert the exact instrument that participants actually completed, including item wording, order, response scale, and any open-ended prompts. No anonymized response matrix is present in the repository version inspected; publish the de-identified item-level responses and the script that computes the means and standard deviations if consent permits, or document a clear audit trail and data-access restriction. Reconcile the demographic source as well. If no open-ended data were collected and analysed, stop calling this a qualitative evaluation or a mixed-method study; describe it as a formative, descriptive questionnaire combined with a quantitative retrieval benchmark. If open-ended data exist, report the coding method and actual themes rather than referring vaguely to qualitative feedback.
Correct the statistical output pipeline before publishing its tables. evaluation/experiment_runner.py currently discards the Wilcoxon statistic and writes 0.0 for every comparison. Store the statistic returned by SciPy, define the zero-difference handling, and handle identical vectors explicitly instead of leaving an unexplained NaN. The confidence intervals in system_summary.csv are t-intervals, not the bootstrap intervals promised in Chapter 6, and several extend above 1.0 for bounded metrics. Use one defensible method, label it accurately, and regenerate the files. Under the current results, fuzzy-versus-semantic differences do not survive Holm correction, so describe only higher point estimates unless the corrected rerun supports a stronger statement.
Gate 2: align the questions, claims, and implemented system

Describe the baselines exactly and discuss the simplest competitor honestly. The so-called metadata-quality baseline is a linear weighted score that includes portal-position relevance as well as recency, completeness, and resources; it is not metadata-only. Name it as a linear multi-criteria or weighted-sum baseline and report the implemented weights. It descriptively outperforms fuzzy on the aggregate metrics and is itself readily interpretable. The discussion must therefore explain what fuzzy rule-based reasoning adds beyond a simpler interpretable weighted sum, and must not imply that fuzzy logic is the only route to transparent ranking.
Recalibrate the Abstract and Chapter 8 only after the corrected rerun. Replace 'successfully supports', 'contributes meaningfully', 'demonstrates', and 'improved' where the design supplies only descriptive or perceptual evidence. Do not claim that explanations caused greater trust or that fuzzy ranking improved retrieval unless a controlled comparison and the corrected statistics support those claims.
Expand the limitations to match the actual design. Add the single-assessor and author-bias limitation; the small 15-query benchmark; portal-generated candidate-set bias and the absence of end-to-end recall measurement; the single portal and 500-dataset scope; hand-designed rules; n=10 and a technically homogeneous sample; the single-condition questionnaire; and the inability to infer that explanations caused changes in understanding or trust. Publishing the complete data and pipeline is a mitigation, not a reason to omit these limitations.
